# 원격 접속 게이트

정해진 두 사람이 **모두** 문자 인증번호(OTP)까지 마쳤을 때만, Apache Guacamole 에 연결된 접근제어 PC 화면을 웹에서 함께 볼 수 있게 하는 웹앱입니다.

```
사용자 A (아이디·비밀번호 → 문자 인증번호) ─┐
                                            ├─▶ 게이트(이 웹앱) ─▶ Guacamole ─▶ 접근제어 PC (Windows)
사용자 B (아이디·비밀번호 → 문자 인증번호) ─┘
```

- 한 사람만 인증한 상태에서는 Guacamole 에 접속조차 하지 않습니다.
- 두 사람은 같은 화면을 봅니다. 조작은 한 사람만 하고, 다른 사람은 보기만 합니다. 조작 중인 사람이 권한을 넘길 수 있습니다.
- 한 사람이라도 로그아웃하거나, 창을 닫거나, 세션이 만료되면 원격 연결이 곧바로 닫힙니다.
- 화면과 키보드·마우스만 오갑니다. 클립보드, 파일 전송, 소리, 프린터는 막혀 있습니다.

## 로컬에서 먼저 써 보기

Node.js 20.6 이상이 필요합니다. 실제 Guacamole 없이, 같은 방식으로 응답하는 연습용 가짜 서버로 흐름을 볼 수 있습니다.

```bash
npm install
npm run hash-password      # 두 번 실행해서 두 사람의 비밀번호 해시를 만든다
copy .env.example .env     # (macOS/Linux: cp) 그리고 USER1_*, USER2_* 를 채운다
npm run mock               # 터미널 1: 가짜 Guacamole (8081)
npm run dev                # 터미널 2: 게이트 (8080)
```

`http://localhost:8080` 을 **서로 다른 브라우저 두 개**(또는 일반 창과 시크릿 창)에서 열어 각각 로그인합니다. `SMS_PROVIDER=console` 이면 인증번호가 문자 대신 게이트를 띄운 터미널에 찍힙니다.

## 운영 배포

### 1. 올릴 곳

- **항상 켜져 있는 서버(컨테이너) 1대**여야 합니다. 화면 연결이 오래 유지되는 WebSocket 이고, 인증 상태를 메모리에만 두기 때문입니다. Vercel 같은 서버리스에는 올릴 수 없고, 인스턴스를 2개 이상으로 늘려도 안 됩니다.
- HTTPS 가 필수입니다. 호스팅 서비스가 HTTPS 를 처리해 주면 `TRUST_PROXY=1`, 직접 받으려면 `TLS_CERT_FILE` / `TLS_KEY_FILE` 을 지정합니다.
- 서버가 다시 시작되면 두 사람 모두 처음부터 다시 인증해야 합니다 (의도한 동작).

```bash
docker build -t remote-gate .
docker run -d --name remote-gate -p 8080:8080 --env-file .env --read-only --cap-drop ALL remote-gate
```

### 2. Guacamole 쪽 준비

1. **게이트 전용 계정**을 하나 만듭니다. 권한은 접근제어 PC 연결 하나에 대한 "읽기(접속)" 뿐이어야 합니다. 관리자 권한, 다른 연결 권한을 주지 마세요. 이 계정에는 TOTP 같은 추가 인증을 걸지 않습니다 (게이트가 자동으로 로그인해야 합니다).
2. **연결 번호 찾기**: Guacamole 에서 그 연결을 열면 주소가 `.../#/client/MQBjAHBvc3RncmVzcWw` 처럼 됩니다. 마지막 부분을 풀면 번호와 데이터 소스가 나옵니다.
   ```bash
   node -e "console.log(Buffer.from('MQBjAHBvc3RncmVzcWw','base64').toString().split('\0'))"
   # [ '1', 'c', 'postgresql' ]  →  GUAC_CONNECTION_ID=1, GUAC_DATA_SOURCE=postgresql
   ```
3. **Guacamole 로 가는 길을 게이트로 한정**합니다. 두 사용자가 Guacamole 에 직접 접속할 수 있으면 이 게이트를 건너뛸 수 있습니다. 게이트 서버의 고정 IP 만 허용하거나, 터널 서비스의 서비스 토큰(`GUAC_EXTRA_HEADERS`)을 요구하도록 하세요. 두 사용자에게는 Guacamole 계정을 주지 않는 것이 맞습니다.
4. 연결 설정에서도 클립보드 복사/붙여넣기, 드라이브·프린터 연결, 소리를 꺼 두면 이중으로 막힙니다.
5. 사설 인증서를 쓰는 Guacamole 이면 Node 의 `NODE_EXTRA_CA_CERTS` 로 인증 기관 파일을 지정합니다. 인증서 검증을 끄는 옵션은 없습니다.

### 3. 환경 변수

전체 목록과 설명은 [`.env.example`](.env.example) 에 있습니다. 꼭 채워야 하는 것:

| 이름 | 내용 |
| --- | --- |
| `NODE_ENV` | `production` |
| `PUBLIC_ORIGIN` | 브라우저에서 접속하는 주소 (예: `https://gate.example.com`) |
| `TRUST_PROXY` 또는 `TLS_*` | HTTPS 처리 방식 |
| `USER1_ID` `USER1_NAME` `USER1_PHONE` `USER1_PASSWORD_HASH` | 첫 번째 사람 |
| `USER2_ID` `USER2_NAME` `USER2_PHONE` `USER2_PASSWORD_HASH` | 두 번째 사람 (번호가 달라야 함) |
| `SMS_PROVIDER` `SMS_FROM` 과 서비스별 키 | 문자 발송 (`solapi`, `sens`, `twilio`) |
| `GUAC_URL` `GUAC_USERNAME` `GUAC_PASSWORD` `GUAC_CONNECTION_ID` | Guacamole 접속 정보 |

비밀 값(`*_PASSWORD_HASH`, `GUAC_PASSWORD`, 문자 서비스 키)은 호스팅 서비스의 시크릿 메뉴에 넣고, 코드나 저장소에는 적지 않습니다. 설정이 빠졌거나 안전하지 않으면(http 주소, console 문자 등) 서버가 이유를 알려 주고 시작하지 않습니다.

## 보안 설계

**인증**
- 1단계 아이디·비밀번호(scrypt 해시), 2단계 문자 인증번호. 비밀번호가 맞아야 문자가 나가므로 남이 문자를 마구 보내게 할 수 없습니다.
- 인증번호: 6자리, 3분, 한 번만 사용, 번호당 5번까지 입력, 로그인 한 번에 3개까지, 사용자당 10분에 5통.
- 비밀번호·인증번호를 15분 안에 10번 틀리면 그 계정은 남은 시간 동안 잠깁니다. IP 당 시도 횟수도 제한합니다.
- 틀린 비밀번호와 없는 아이디는 응답과 걸리는 시간이 같습니다.
- 세션: 인증 성공 시 새 값 발급, `HttpOnly` `Secure` `SameSite=Strict` 쿠키, 사용자당 1개(새로 인증하면 이전 것은 끊김), 화면을 떠난 지 2분 또는 인증 후 2시간이면 만료.

**두 사람 규칙**
- 원격 터널은 두 사람의 인증된 화면 연결이 모두 붙어 있는 동안에만 존재합니다. 서버가 10초마다 다시 확인합니다.
- Guacamole 계정과 토큰은 서버만 가지고 있고 브라우저로 나가지 않습니다. 연결이 끝나면 토큰을 폐기합니다.

**오가는 내용 제한**
- 브라우저 → 원격 PC: 조작 권한이 있는 사람의 키보드·마우스 입력만, 형식 검사를 거쳐 서버가 다시 만들어 보냅니다. 화면 크기 변경, 클립보드, 파일 등 그 밖의 명령은 버립니다.
- 원격 PC → 브라우저: 화면을 그리는 명령만 통과합니다. 클립보드·파일·소리·영상·기타 데이터는 서버에서 막고 Guacamole 에 거절 응답을 보냅니다.

**웹**
- 다른 사이트에서 보낸 요청과 화면 연결은 거부합니다(Origin, 전용 헤더, `SameSite`). 설정한 주소가 아닌 이름으로 온 요청도 거부합니다.
- 엄격한 콘텐츠 보안 정책(외부 스크립트·인라인 스크립트 불가), 프레임 삽입 금지, HSTS, 캐시 금지.
- 내려 주는 파일은 정해진 4개뿐이고, 요청 크기와 속도에 상한이 있습니다.

**기록**
- 로그인 성공·실패, 인증번호 발송, 화면 연결, 원격 연결 시작·종료, 조작 권한 이동, 막은 데이터 종류를 JSON 한 줄씩 표준 출력에 남깁니다. 인증번호·비밀번호·세션 값은 남기지 않고 전화번호는 가립니다. 호스팅 서비스의 로그 보관 기능으로 모아 두세요.

## 알아 둘 한계

- **문자 인증번호의 한계**: 유심 복제·번호 이동 사기, 통신망 가로채기, 속여서 번호를 받아 내는 수법에는 문자 방식 자체가 약합니다. 더 강하게 하려면 인증 앱(TOTP)이나 보안 키로 바꾸는 것이 좋습니다.
- **두 사람이 "같이 있다"는 보장은 접속 기준**입니다. 두 사람의 인증 정보를 한 사람이 모두 갖고 있으면 혼자서도 열 수 있습니다. 휴대폰과 비밀번호를 각자 관리해야 합니다.
- **화면 캡처는 막을 수 없습니다.** 클립보드와 파일은 막지만, 보이는 화면을 사진으로 찍는 것은 기술적으로 막지 못합니다.
- 원격 연결을 닫아도 Windows 로그인 상태는 PC 쪽 정책을 따릅니다. 연결이 끊기면 화면이 잠기도록 Windows 에서 설정해 두세요.
- 한글 입력기 전환 등 일부 키는 브라우저·운영체제 조합에 따라 원격으로 전달되지 않을 수 있습니다.
- 계정 잠금은 누군가 아이디를 알고 일부러 틀리면 정상 사용자도 15분간 막히는 부작용이 있습니다.
